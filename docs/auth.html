00الفكرة في سطرين

المستخدم يبعت الإيميل وكلمة السر مرة وحدة، فيرجعله Laravel توكن (زي كرت دخول). بعدها كل طلب يبعت معاه الكرت في الـ header، وLaravel يعرف مين هو بدون ما يطلب كلمة السر مرة ثانية.

Accept: application/json

SPA cookies (session + CSRF)React على نفس الدومين بسلا معقدة وما تخدمش مع Flutter

01الفلو من فتح التطبيق

الترتيب هنا مهم، فالخطوات مرقمة. الـ login ما يحتاجش توكن، والتحقق من التوكن يصير بـ /me.

1فتح التطبيقعنده توكن محفوظ؟ لو لا، يمشي لشاشة الدخول.
2GET /meمع التوكن. 200 داخل. 401 يمسح التوكن ويمشي للدخول.
3POST /loginإيميل + كلمة سر، بدون توكن. يرجّع توكن جديد.
4يحفظ التوكنFlutter: flutter_secure_storage. React: الذاكرة أو localStorage.
5كل طلبauth:sanctum ← active ← role ← الكنترولر.
6POST /logoutيمسح التوكن الحالي من الداتا بيس.

    personal_access_tokens: علاقة 1 لـ N

    كل login يعمل صف جديد. مفتش دخل من تليفونين يكون عنده توكنين، والاثنين يأشّروا على نفس users.id.

    users                     personal_access_tokens
id=2  ───────────┬──────► id=1  tokenable_id=2  name=flutter
                 ├──────► id=7  tokenable_id=2  name=flutter   (second phone)
                 └──────► id=9  tokenable_id=2  name=flutter

    Sanctum يعمل الربط بـ morphs('tokenable')، يعني عمودين (tokenable_type وtokenable_id) بدون FK حقيقي، فلو انمسح المستخدم تقعد توكناته يتيمة. وعندنا User بس ياخذ توكنات، فنزيد FK مع cascade، ونخلي الأسماء كما هي لأن Sanctum يدوّر عليها بالاسم:

    // بعد: php artisan vendor:publish --tag=sanctum-migrations
Schema::create('personal_access_tokens', function (Blueprint $table) {
    $table->id();
-   $table->morphs('tokenable');
+   $table->string('tokenable_type');
+   $table->foreignId('tokenable_id')->constrained('users')->cascadeOnDelete();
+   $table->index(['tokenable_type', 'tokenable_id']);
    $table->text('name');
    $table->string('token', 64)->unique();   // hash, not the plain token
    $table->text('abilities')->nullable();
    $table->timestamp('last_used_at')->nullable();
    $table->timestamp('expires_at')->nullable()->index();
    $table->timestamps();
});

    05الـ login خطوة خطوة

    public function login(Request $request)
{
    $data = $request->validate([
        'email'    => ['required', 'email'],
        'password' => ['required', 'string'],
    ]);

    $user = User::where('email', $data['email'])->first();

    // 1. same message for wrong email or wrong password
    if (! $user || ! Hash::check($data['password'], $user->password)) {
        return response()->json(['message' => 'Invalid credentials'], 401);
    }

    // 2. account switched off
    if (! $user->is_active) {
        return response()->json(['message' => 'Account disabled'], 403);
    }

    // 3. role must match the app
    $app     = $request->route()->defaults['app'];          // flutter | react
    $allowed = $app === 'flutter' ? ['inspector'] : ['supervisor', 'admin'];
    if (! in_array($user->role, $allowed)) {
        return response()->json(['message' => 'Use the other app'], 403);
    }

    // 4. one session per app (optional): drop the old token
    $user->tokens()->where('name', $app)->delete();

    // 5. new token + last login
    $token = $user->createToken($app, [$user->role])->plainTextToken;
    $user->forceFill(['last_login_at' => now()])->save();

    return response()->json([
        'token'                => $token,
        'user'                 => $user->load('employee'),
        'must_change_password' => $user->must_change_password,
    ]);
}

    رسالة الخطأ وحدة للإيميل الغلط وكلمة السر الغلط، عشان ما حدش يقدر يعرف أنهي إيميلات موجودة. وforceFill لأن last_login_at مش في $fillable.

public function logout(Request $request)
{
    $request->user()->currentAccessToken()->delete();   // this device only

}

    06is_active: ثلاث بوابات

    قفل الحساب وحده ما يطلّعش المستخدم، لأن التوكنات القديمة لسا صالحة. عشان هذا الشرط يتحط في ثلاث أماكن، وكل وحدة تسكّر باب:

    في الـ loginif (! $user->is_active) ← 403. يمنع دخول جديد.
    وقت القفل$user->tokens()->delete() مع is_active = false. يطلّعه من كل الأجهزة فوراً.
    middleware activeعلى كل route محمي. احتياط لو حد قفل الحساب من pgAdmin مباشرة.
    // app/Http/Middleware/EnsureUserIsActive.php
public function handle(Request $request, Closure $next)
{
    if (! $request->user()?->is_active) {
        $request->user()?->currentAccessToken()?->delete();
        return response()->json(['message' => 'Account disabled'], 403);
    }
    return $next($request);
}

// app/Http/Middleware/EnsureRole.php   usage: role:inspector  or  role:supervisor,admin
public function handle(Request $request, Closure $next, string ...$roles)
{
    if (! in_array($request->user()->role, $roles)) {
        return response()->json(['message' => 'Forbidden'], 403);
    }
    return $next($request);
}

    الكودمتىالتطبيق يدير

    429محاولات login كثيرة (throttle)يستنى دقيقة

    09ترتيب الشغل

    • Sanctum مركّب، وHasApiTokens في User
    • أعمدة is_active وmust_change_password وlast_login_at وtimestamps في ملف users
    • vendor:publish --tag=sanctum-migrations وتعديل الـ FK مع cascade
    • migrate:fresh (يمسح بيانات السيرفر، ويطبق employee_no وusers والتوكنز مع بعض)
    • casts في User: is_active وmust_change_password boolean، وlast_login_at datetime
    • Seeder لأول مشرف، والبيانات من .env
    • AuthController: login و me و logout
    • Middleware active وrole، وتسجيلهم في Kernel.php
    • Routes في flutter.php وreact.php
    • تجربة بـ Postman: login ← me ← logout ← me (لازم 401)
